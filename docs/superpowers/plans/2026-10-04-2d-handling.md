# 2D Handling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One handling model for 2D views. It covers:
- smoothing, coasting, double-click reset, a zoom range of 0.1× to 64×, pinch and the keyboard;
- no accidental text selection;
- hover and select;
- focus by coordinates (`@focus:`) and a coordinate tool.

Geometry figures get it first.

**Architecture:**
- A pure, DOM-free core in `graph-engine/src/view2d/` decides everything and is tested in node with a fake clock.
- A thin browser layer in `view2d/dom/` plumbs native events and a frame loop into it.
- The figure renderer keeps its SVG byte-identical, and additionally returns its author frame and hit items, which FigureView feeds to the core.

**Tech stack:** TypeScript, React 18, vitest (node-only, `*.test.ts`), Vite, oxlint.

**Spec:** `docs/superpowers/specs/2026-10-04-2d-handling-design.md`. Read it first; it is the authority. Where this plan and the spec disagree, the spec wins, unless a ruling below says otherwise.

## Global Constraints

**The renderer**
- **The SVG is byte-identical.** `renderFigure`'s `svg` must be identical for every example, under clean and every preset. `figure/cleanGolden.test.ts` passes untouched. Task 4 carries the sweep that proves it.
- **New information travels in the return value, never in the markup.** `renderFigure` returns `{ svg, errors, frame, items }`.

**The core**
- **Pure:** `view2d/*.ts` (not `view2d/dom/`) imports nothing from `figure/`, `parser/`, React or the DOM. Time is always a parameter (`t`, in ms); there is no `performance.now()` in the core.
- **Tunable:** every number in Spec §"The model" lives in `view2d/feel.ts` as a named constant.

**The rules**
- **Exact where it matters.** A zoom keeps the content point under the cursor (or between the fingers) fixed. A drag tracks the cursor exactly. Smoothing changes when the view arrives, never where.
- **No text selection** inside a handled view, ever.
- **Reduced motion:** with `prefers-reduced-motion: reduce`, moves are instant and nothing coasts.

**Tests and checks**
- Tests are node-only. Components hold only plumbing, so every decision has a test.
- Proving a test can fail means deleting the behaviour it covers and seeing it go red. Record how in the task report.
- Commands, from `graph-engine/`:
  - tests: `npx vitest run --maxWorkers=2`;
  - typecheck: `npx tsc -p tsconfig.app.json --noEmit` and `npx tsc -p tsconfig.node.json --noEmit` (bare `npx tsc --noEmit` checks nothing);
  - lint: `npm run lint`.

**Working alongside others**
- Several agents work in this repo at once, in other worktrees and branches; unfamiliar branches or stash entries are expected.
- Stage with explicit `git add <paths>` only. Never `git stash`. No push, no merge.
- Don't start dev or review servers, and never use port 5182.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.

**Ruling (pan margin, made at planning):** "at least 15% of the content frame stays on screen" is impossible when zoomed in past about 6×. The rule is therefore: in each axis, the visible rect overlaps the content frame by at least `keep = min(PAN_MARGIN × frame size, visible size / 2)`. At fitted zoom that is 15% of the frame. Zoomed in, it means at least half the screen stays on content.

  readonly target: Camera

`feel.ts` holds exactly these constants:

```ts
// Every number that decides how a 2D view feels, in one place. Times are in
// milliseconds, distances on screen in CSS pixels, zoom relative to the
// fitted view. Engines read these; Ben tunes them here.
export const ZOOM_MIN = 0.1
export const ZOOM_MAX = 64
// The least a view keeps of its content in each axis, as a fraction of the
// content frame (or half the screen, when zoomed in past that; see limits.ts).
export const PAN_MARGIN = 0.15
// Exponential approach for smoothed moves (wheel, keys): about 4τ to arrive.
export const SMOOTH_TAU = 70
// Coasting after a drag: the velocity of the last COAST_WINDOW ms carries on
// and decays with COAST_TAU; it stops below COAST_STOP px/s. A release after
// holding still for COAST_HOLD ms or more does not coast.
export const COAST_WINDOW = 80
export const COAST_TAU = 300
export const COAST_STOP = 5
export const COAST_HOLD = 80
// Reset and focus: an ease-out cubic over this long (the 3D engine's reset).
export const EASE_DURATION = 280
// Input.
export const WHEEL_SENSITIVITY = 0.0015       // per wheel pixel
export const PINCH_WHEEL_SENSITIVITY = 0.01   // ctrl + wheel: a trackpad pinch
export const WHEEL_LINE_PX = 16               // deltaMode 1
export const WHEEL_PAGE_PX = 400              // deltaMode 2
export const KEY_ZOOM_STEP = 1.25
export const KEY_PAN_FRACTION = 0.1
export const CLICK_SLOP = 4                   // px: under this a press is a click
export const DOUBLE_CLICK_MS = 300
export const DOUBLE_CLICK_SLOP = 6
export const HOVER_TOLERANCE = 8              // px, mouse and pen
export const TOUCH_TOLERANCE = 16             // px, touch
// Below these the smoothed view counts as arrived and snaps.
export const ARRIVE_PX = 0.05
export const ARRIVE_LOG_ZOOM = 1e-4
```

**Rules:**
- **Camera geometry.**
  - `basePxPerUnit = min(screen.width / frame.width, screen.height / frame.height)`.
  - `pxPerUnit = base × zoom`.
  - `visibleRect` is centred on `(cx, cy)`, of size `screen / pxPerUnit`.
  - Screen origin is the top-left; content y points down, as in SVG.
- **`zoomAbout`** keeps `screenToContent(screenPoint)` identical before and after. Zoom is multiplied by `factor`; it is not clamped here.
- **`clampCamera`:**
  - Zoom is clamped to `[zoomMin, zoomMax]`, keeping the centre.
  - Then, per axis, with `half = visible size / 2` and `keep = min(panMargin × frame size, half)`, the centre is clamped to `[frame.min − half + keep, frame.max + half − keep]`.
- **`ViewMotion` smoothing.**
  - The target is always clamped.
  - Each `step(t)` moves current toward target with `alpha = 1 − exp(−dt / SMOOTH_TAU)`, interpolating `log(zoom)` and the centre.
  - When a smoothed zoom has an anchor (`zoomAt`), the centre is derived from the interpolated zoom, so the anchor's content point stays at the anchor's screen point **at every step**.
  - Snap to the target when within `ARRIVE_PX` on screen and `ARRIVE_LOG_ZOOM` in log zoom.
- **Drag and pinch are exact** (current = target). Drag records `(t, dx, dy)` samples.
- **Coasting.**
  - On `dragEnd`, if the newest sample is older than `COAST_HOLD`, there is no coast.
  - Otherwise the velocity is the displacement summed over the last `COAST_WINDOW` ms, divided by the window.
  - Each step pans by `v × dt` and then decays `v *= exp(−dt / COAST_TAU)`. It stops below `COAST_STOP` px/s, or when clamping stopped the move.
- **`animateTo`:**
  - It runs an ease-out cubic `1 − (1 − u)^3` over `EASE_DURATION`, interpolating log zoom and the centre, to the clamped camera.
  - Any `dragStart`, `zoomAt`, `pinch` or `panBy` interrupts it; the move starts from wherever the view is.
- **Reduced motion:** `zoomAt`, `panBy` and `animateTo` set current = target at once, and `dragEnd` never coasts.

// input.ts
export type PointerKind = 'mouse' | 'pen' | 'touch'
export interface PointerSample { id: number; x: number; y: number; t: number; kind: PointerKind; button: number } // x, y relative to the view, px
export interface WheelSample { x: number; y: number; deltaY: number; deltaMode: 0 | 1 | 2; ctrlKey: boolean; t: number }
export interface KeySample { key: string; t: number }
export type Intent =
  | { kind: 'dragStart'; t: number }
  | { kind: 'drag'; dx: number; dy: number; t: number }
  | { kind: 'dragEnd'; t: number }
  | { kind: 'zoom'; at: Vec; factor: number; t: number }                           // smoothed (wheel, keys)
  | { kind: 'pinch'; at: Vec; factor: number; dx: number; dy: number; t: number }   // exact (two fingers)
  | { kind: 'pan'; dx: number; dy: number; t: number }                             // smoothed (keys)
  | { kind: 'click'; at: Vec; pointer: PointerKind; t: number }
  | { kind: 'hover'; at: Vec | null; pointer: PointerKind }                          // null: the pointer left
  | { kind: 'reset'; t: number }
  | { kind: 'clearSelection' }
  | { kind: 'toggleCoordinates' }
export class GestureRecognizer {
  constructor(options?: { screen?: () => { width: number; height: number } })      // for key pans
  pointerDown(s: PointerSample): Intent[]
  pointerMove(s: PointerSample): Intent[]
  pointerUp(s: PointerSample): Intent[]
  pointerCancel(s: PointerSample): Intent[]
  pointerLeave(kind: PointerKind): Intent[]
  wheel(s: WheelSample): Intent[]
  key(s: KeySample): Intent[]
}

// pointing.ts
export type HitShape =
  | { kind: 'point'; at: Vec }
  | { kind: 'segment'; a: Vec; b: Vec }
  | { kind: 'polyline'; points: Vec[]; closed: boolean }
  | { kind: 'circle'; center: Vec; radius: number }
  | { kind: 'arc'; center: Vec; radius: number; start: number; end: number } // radians; point at angle t is center + r(cos t, sin t); from start toward end
  | { kind: 'polygon'; points: Vec[] }   // an area
  | { kind: 'rect'; rect: Rect }         // an area
export interface HitItem { id: string; shape: HitShape; rank?: 0 | 1 | 2 } // rank defaults: point and rect-label 0? No: see rules
export function shapeRank(shape: HitShape): 0 | 1 | 2
export function distanceToShape(p: Vec, shape: HitShape): number         // 0 inside an area
export function hitTest(items: readonly HitItem[], at: Vec, tolerance: number): HitItem | null
export class PointerSelection {
  readonly hovered: string | null
  readonly selected: string | null
  hover(id: string | null): boolean     // true if it changed
  click(id: string | null): boolean     // select id, or clear on null; true if it changed
  clear(): boolean
}
```

**Rules:**
- **Primary button only** for mouse (`button === 0`); every touch and pen.
- **Click or drag.** A press that has moved less than `CLICK_SLOP` px when it is released is a `click` and emits no drag intents. The first move past the slop emits `dragStart` plus a `drag` for the whole displacement since the press, so the drag is still exact.
- **Double-click.** Two clicks within `DOUBLE_CLICK_MS` and `DOUBLE_CLICK_SLOP` px emit the second click's `click` followed by `reset`. A third click starts a new pair.
- **Two pointers down (touch):**
  - The single-pointer drag ends (`dragEnd`), and each move emits `pinch` with `factor = distance / previous distance`, `at` = the current midpoint, and `dx, dy` = the midpoint's delta.
  - When one finger lifts, the other continues as a fresh drag (`dragStart`) from where it is, with no jump.
  - A pinch never emits `click`.
- **Wheel:**
  - Convert the delta to px by `deltaMode` (×1, ×`WHEEL_LINE_PX`, ×`WHEEL_PAGE_PX`).
  - `factor = exp(−deltaPx × sensitivity)`, where sensitivity is `PINCH_WHEEL_SENSITIVITY` when `ctrlKey` (a trackpad pinch) and `WHEEL_SENSITIVITY` otherwise.
  - It emits `zoom` at `(x, y)`.
- **Hover** is emitted on moves only for `mouse` and `pen`, and only when no button is down. `pointerLeave` emits `hover` with `at: null`.
- **Keys:**

  | Key | Intent |
  |---|---|
  | `+` or `=` | `zoom` ×`KEY_ZOOM_STEP` at the screen centre |
  | `-` or `_` | `zoom` ÷`KEY_ZOOM_STEP` at the screen centre |
  | ArrowLeft / Right / Up / Down | `pan` by `KEY_PAN_FRACTION` × screen width or height (ArrowRight moves the content left, so `dx = −fraction × width`) |
  | `0` | `reset` |
  | `Escape` | `clearSelection` |
  | `c` or `C` | `toggleCoordinates` |

  Other keys emit nothing.
- **Pointing.**
  - `shapeRank`: point is 0; segment, polyline, circle and arc are 1; polygon and rect are 2.
  - `hitTest` keeps items whose distance ≤ tolerance (areas: inside = 0).
  - It picks the lowest rank, then the smallest distance, then the **later** item (drawn on top).
  - Arcs measure the distance to the arc only, not the full circle.
  - `PointerSelection` is single-select: `click(null)` clears.

// focus.ts
export type FocusTarget =
  | { kind: 'plane'; x: number; y: number }
  | { kind: 'space'; x: number; y: number; z: number }
  | { kind: 'view'; u: number; v: number }          // the engine's own content units
export interface FocusSpec { target: FocusTarget; zoom: number }
export function parseFocus(value: string): FocusSpec        // throws Error naming the valid forms
export function formatFocus(spec: FocusSpec): string        // the value only: "(3, 2) zoom 4"
export interface AuthorMapping { toContent(target: FocusTarget): Vec | null } // null: this engine cannot place that form
export function focusCamera(spec: FocusSpec, mapping: AuthorMapping): Camera | null

// readout.ts
export function formatCoordinate(n: number): string          // up to 3 decimals, trailing zeros trimmed, "-0" → "0"
export function formatPoint(values: readonly number[]): string // "(1.5, -2)"
export function formatZoom(zoom: number): string             // "4×", "0.25×", "12.5×": 3 significant figures, trimmed

// parser/config.ts
GraphConfig.focus: FocusSpec | null   // default null
```

**Rules:**
- **Grammar:** `@focus: <target> [zoom <k>]`.
  - `<target>` is `(x, y)`, `(x, y, z)` or `view (u, v)`.
  - Numbers are optionally signed decimals, with an optional exponent.
  - Spaces are free, and `zoom` is case-insensitive.
  - `k` must be greater than 0, and defaults to 1.
- **Refusals** throw an `Error` whose message lists the three forms:
