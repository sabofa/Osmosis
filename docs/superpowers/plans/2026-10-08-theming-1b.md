### B1.3 — ownership + `compose()` (≤150 lines)
**Files:** `theme-core/src/layers.ts` (new), `layers.test.ts`, barrel.
**Produces (exact, 1B §3.1–3.2):**
```ts
export type Owner = 'workspace' | 'ambience' | 'shared'
export function ownerOf(tokenName: string): Owner          // throws Error on unknown token
export const OWNED_DIALS: { workspace: readonly (keyof Dials)[]; ambience: readonly (keyof Dials)[] }
export interface IgnoredField { layer: 'workspace' | 'ambience'; themeId: string; path: string; reason: string }
export interface LayerSet { workspace?: ThemeManifest | null; ambience?: ThemeManifest | null }
export function compose(layers: LayerSet): { manifest: ThemeManifest; ignored: IgnoredField[] }
```
Ownership rules: tokens with `group` in {type (except `font-math`), shape (incl. `icon-sheet`, `corner-shape`), space, elevation, motion, component} ⇒ workspace; groups {colour, surface, graph, document} ⇒ ambience **except** `font-math`, `doc-font-body`, `doc-measure` ⇒ shared. Dials: workspace = roundness density elevation borders motion typeScale baseSize; ambience = contrast saturation warmth translucency texture twilightBlend. `compose`: neither ⇒ `builtinById(DEFAULT_THEME_ID)` (same object); exactly one present ⇒ that manifest returned **by identity**, `ignored: []`; both ⇒ new manifest per 1B §3.2 (id `ws.id+'+'+amb.id`, name `ws.name + ' · ' + amb.name`, seeds from ambience; dials per OWNED_DIALS; fonts display/body/mono from workspace, math from ambience ?? workspace; overrides.any/light/dark filtered by `ownerOf` — workspace keeps {workspace, shared}, ambience keeps {ambience, shared}, ambience wins shared clashes; `css = ws.css + '\n' + amb.css` (omit empty parts); `graph` from ambience; `ambience/sounds/assets` from ambience by identity; `workspace` from workspace by identity; `description/author` from ambience); every dropped field is recorded in `ignored`. Inputs are never mutated. Unknown override token names (not in the registry) are dropped into `ignored` with reason 'unknown token' (validate catches them first).
**Tests:** `ownerOf` total over all of `TOKENS` and spot checks (radius-md ws, color-accent amb, button-primary-bg ws, font-math shared, doc-font-body shared, icon-sheet ws, graph-grid amb, doc-page amb, shadow-1 ws, surface-alpha amb); OWNED_DIALS disjoint and cover all numeric dials + twilightBlend; compose: identity for 0/1 layers; the 1B §6 example (workspace `roundness:0`, `overrides.any['corner-shape']='bevel'`, `fonts.body`, `css`; ambience seeds + `dials.contrast` + `ambience:{x:1}` slot + its own `roundness`/`overrides['radius-md']` that must land in `ignored`); css order workspace→ambience; shared clash ambience wins; deep-frozen inputs untouched; `resolve(compose(...).manifest)` works for every pair of {ws-clean, retro-like fixture} × {the 4 builtin ambience themes}; composed `toLegacyTokens` equals the ambience theme's alone when the workspace theme is `ws-clean` (parity).
**Acceptance:** suites green; ws-clean + each builtin resolves to the same tokens as the builtin alone (assert deep-equal of `resolve().light/dark` for every builtin).

### B1.4 — validate: ownership warnings (≤120 lines)
**Files:** `theme-core/src/validate.ts`, `validate.test.ts`.
**Rules (1B §4):** when `manifest.layer` is `'workspace'` or `'ambience'`, add a **warning** (never an error) for each field outside its ownership: path `seeds…`, `dials.<k>`, `overrides.<mode|any>.<token>`, `fonts.<role>`, `graph`, `ambience`, `sounds`, `assets` (ambience-owned seen in a workspace theme) / `workspace` (workspace-owned seen in an ambience theme); message `"<path> is ignored in a <layer> theme (owned by the <other> layer)"`, no suggestion. `full` themes (no `layer`) get none. The contrast/series warnings for a layer theme are computed on `compose({workspace: m, ambience: null})` / `({workspace: null, ambience: m})` respectively **with the other side = the default for its kind** (workspace theme ⇒ composed over `builtin:osmosis`; ambience theme ⇒ composed under `builtin:ws-clean`), so a layer theme is judged on what it renders. Also warn (informational) on `css` containing `@import` in a workspace theme.
**Tests:** one warning per owner class both directions; none for a full theme; a workspace theme with seeds ⇒ warning at `seeds`; ownership warnings don't flip `ok`; ws-clean and the four builtins stay warning-free; contrast warning still produced for a bad-ink ambience theme.
**Acceptance:** suites green. **Task B1 ends with one Sonnet review of B1.1–B1.4.**
